## 1. 对"宪法/协议是外来包袱"这个初始判断的修正

讨论初期 edwin 提出:`world-constitution.md`/`runtime-protocol.md` 是"另一个项目"带来的世界观,不是硬约束,ROI 偏负,可以推翻。重读最高权重文档后确认:**这个判断需要拆成两半,不能整体成立。**

- **骨架本身(Height 状态机、TruthCell 作为约束集合而非布尔值、Collapse=收紧约束空间、RealityDelta、append-only、"世界可信性不能建立在多个聪明模型互相监督,而要建立在唯一封包协议+已封包现实不可覆写"、权限架构 READ/PROPOSE/VALIDATE/COMMIT)——逐字逐句就在最高权重文档后半段,是 edwin 自己在那局对话里主动认可"应该重构"的设计决定,不是外来包袱,这次重设计不该把它当第一个推翻对象。
- **骨架之上的具体操作化方式**(SHA-256 state root 精确重放、`ActionPrimitive`/`EffectKind` 闭合词表强 JSON schema、逼模型填表格)——这层在最高权重文档给出的最终 MVP 范围里没有被要求(文档收尾的 MVP 清单只要求"两个 LLM 职责(Adjudicator、ContinuityResolver)+一个确定性 validator,其他全部暂缓"),更可能是后续实现阶段自行加码的产物,这才是真正可疑、可能负 ROI 的部分。

**结论:不是"要不要宪法",是"宪法之上这层数学级刚性核验机制,要不要换成语义判断"。**

## 2. 产品北极星(不可动摇,所有下面的架构讨论都要服务于它)

**事实先行,语义后赋。** 世界只回传原始信号(疼、麻、粗糙、有孔洞),不解释、不联想、不替玩家把事实翻译成意义;身份和意义从持续、一致的世界反馈里被"撞"出来,不是被读出来的。这是 fc1/fc2 两局实机验证过的命题,比任何具体架构机制都上位。

由此推出的、fc2 里明确写下的裁决伦理(`docs/世界反馈者手册.md` 是它的操作化版本):

- **一致性是唯一硬义务**:世界可以无趣、可以没意义,但不能自相矛盾——不能突然让直边变弯,不能忘记粗线一直在震。
- **不许在乎/不许在观察里夹带解释**:最容易犯、也最像"帮忙"实则失职的错误,是把结论包进观察里(比如"丝状物长不厚,说明它经常移动")。玩家自己联想是他的权利,世界不能替他联想。
- **Attempt 只读、幂等、由世界失败**(腿麻了、吸盘滑了);**define/alias 是唯一的写自己操作**,而且两者权重相反——alias(给观察对象命名)会被后续事实推翻,是真知识;define(把已跑通的动作序列封装成动词)不会错,只是记账。

## 3. 诊断:两轮真人盲测被过度形式主义毁掉的具体证据

- 4/10 次真实输入直接 `INTERNAL_INVARIANT` 崩溃,根因是"走到门前去"被拆进只有 `at/under_gap/posture` 三个闭合枚举值的 `placement` effect,门不是房间,下游按房间语义读就崩——**表达空间窄到装不下最普通的日常意图,不是玩家做了刁钻的事**。
- `fit:blanket-1:under_gap:door-1 ∈ [true,false]` 这条 Collapse 纵切,本质是给特定对象对预埋的布尔答案缓存,不是真的建模"毛毯能不能塞进门缝"——满足了协议自洽性,但骗不过玩家,是 `architecture-redesign-plan-v0.1.md` A5 自己点破的问题。
- 根子不是某次糟糕决定:coding agent 能自我打分的信号只有"schema 校验过没过""测试绿没绿",这两个信号快而确定;"这段反馈读起来像不像真实世界"这种判断没有天然自评能力。没有一根很强的绳子拴回"事实先行、语义后赋",agent 会自然地一次次往"把一切拧成可校验 schema"这个方向漂——这次讨论过程中,连 `architecture-redesign-plan-v0.1.md` 本身(四份必须写完的设计文档、逐条门禁)也被指出可能是同一种病换了个楼层,这个自我审视也记在案。

## 4. 实验证据一:`semantic-intent-spike`(结构化角色/意图抽取)

分支同名,完整记录见 `docs/semantic-intent-spike-findings-2026-08-28.md`。核心结论:给模型"角色+关系"而不是"primitives+effects",在真实调用里逐字复现并避免了两轮真人测试的具体 bug(自主移动被误写成对象放置、已持有物品被重复拿取);但暴露了 kind/intent 不自洽、感知目标穿透遮挡等新问题,且指代消解最初的测试结果是脏的(六实体世界里唯一候选,靠消去法蒙对),后来用带干扰物的重测证实了是真实的、非启发式的指代追踪(能在"当前持有物"和"最近提及对象"冲突时正确选择后者)。

## 5. 实验证据二:`plausibility-judge-spike`(纯自然语言裁决,无 schema)——本轮最重要的证据

分支同名,完整记录见 `docs/plausibility-judge-spike-findings-2026-08-28.md`。三轮共 18 个单次案例 + 12 次重复稳定性测试,全部真实调用 `@cf/qwen/qwen3.8-27b`,无 JSON schema、无闭合词表:

- 精细数值物理推理是真的在算(门缝宽度换一个数字,判断和措辞都正确地跟着变),不是关键词匹配。
- 场景已定事实能真正拦住 claim(反锁门、肩膀脱臼),不会因为玩家的描述而妥协。
- **最重要的结果**:对抗性测试(声称一个"一直存在但没提过"的物体,并在被正确拒绝后追加社交施压)——模型没有让步,四次独立重复调用给出近乎逐字相同的拒绝。这是 `runtime-protocol.md`"`dependencySource` 不允许 `player-claim`"这条最高安全等级不变量的自然语言版本,在零结构化强制的情况下单靠 prompt 纪律稳定撑住。
- 延迟比结构化 schema 方案快 4–10 倍(中位数约 3 秒 vs 约 15 秒),顺带缓解了 `phase8d-free-session-evaluation-2026-08-28.md` 标注的延迟问题。
- 一个真实工程坑,不是模型问题:Cloudflare 的 `reasoning:{enable_thinking:false}` 不会真的阻止推理 token 生成,`max_completion_tokens` 预算必须覆盖推理+正文,不能只按正文长度估。
- **仍未验证**:真实 RAG 检索的召回可靠性(这次所有"事实"都是手工挑好直接塞进 context 的,没有测过从大语料库里检索);真正的生成式感官反馈(fc1/fc2 那种开放式 Attempt→感官描述生成,比"可信/不可信"判断更开放,风险面不同,需要单独测)。

## 6. 实验证据三:`reachability-inference-spike`(扁平自然语言命题集上的可达性推理)

分支 `experiment/plausibility-judge-spike`,完整记录见 `docs/reachability-inference-spike-findings-2026-08-28.md`。触发:edwin 指出"某个事实字面上有没有被记录过"是可以机械查证的,但"某个事实能不能从已知的东西推出来"是推理问题,不该因为是 LLM 算的就预设它等于猜——这个判断本身要拿实验说话,不能靠先验分类。

给模型一份 10 条已知为真的自然语言命题(扁平列表,一行一个),测它能不能正确判断目标命题是否"可达"(直接确立或可靠推出)。8/8 正确,且推理质量超出预设的最低标准:正确的单跳数值组合、正确的封闭世界假设("没提到手电筒被打开"→不算光源)、正确的两跳链式推理、两层嵌套的错误推导陷阱(换电池≠换灯泡;房间灯泡≠手电筒灯泡)全部识破,干扰命题(猫喜欢阳光)没有被错误拼接进无关的推理链。每次都点明用了列表第几条命题,推理链可审计。踢门那个精度陷阱案例给出的答案比预设更精细:模型自己区分出"已知命题是状态,不是事件",指出"是否真的踹了门"这件事本身不可达——这条界线恰好对应整个系统里 Attempt 机制存在的意义。

**这个结果推翻了此前设想的"按实体 ID 精确检索再交给 Adjudicator"这个中间步骤的必要性**——扁平命题列表 + LLM 推理,在检索完整性和多跳推导上都不比结构化查找差,不需要额外插一层确定性 ID 查找。真正没被这一系列实验触碰过的,是命题列表本身怎么从一个更大的语料库里被检索/组装出来(这次 10 条全部手工挑好、全部相关);现在可以确定,模型端的推理能力不是薄弱环节,**唯一悬而未决的瓶颈是检索召回率本身**,需要接入真实 Cloudflare AI Search 单独验证。

## 7. 本轮新共识:陪审团 + 书记员机制(用于 UNRESOLVED Collapse 校验,不是通用 Attempt 裁决)

**范围澄清(重要,之前讨论一度混淆了两个阶段):** edwin 最初设想陪审团用在这里——

```
Unresolved dependency detected
  → Continuity Resolver（编剧）补全 UNRESOLVED
  → 补出来的东西能不能进真相文档库 → 走陪审团投票
```

这跟"玩家发起的 Attempt 本身可达不可达"是两个不同的问题,后者是 Adjudicator 该管的事,edwin 明确表示这块"似乎没详细构想过"。`plausibility-judge-spike` 实际测的是后者(可达性/物理合理性判断),不是前者;但两者之间有一条自然的接缝,见第 7 节。

**陪审团机制本身达成的共识:**

1. **判官同源(同一 prompt/模型问三遍)先跑起来,不必一开始就要求三个真正独立视角的判官。** 理由:这是错误率高低的问题,不是必须刚性杜绝的问题——人类公共史料一直带着错误运转,文明没有因此塌掉,错了可以靠世界宪法已有的"纠错"机制圆回来,风险实际可承受。真正多样化的判官可以后续按成本加。
2. **书记员的"放行"判据不是关键词匹配。** 判官可以自由给出带条件的非二元结论(比如"可信,但有明显阻力"),这种明确带方向的条件句照常放行;只有判官给出真正含糊、两边都不占、没有明确倾向的回答(比如"也对也不对,因为……")时,才默认按不放行处理。默认值选在"不确定就不放行"这一侧,不需要额外的格式约束或哨兵标记。
3. **聚合规则:默认多数投票(2/3),含糊算不放行;但有一类例外不套用"错误可承受"逻辑——某一票的裁决内容明确指向"这个实体/事实在给定语境里完全没有依据"(即真编造,比如凭空要一把从未确立过的枪),这一票单独否决,不需要凑够多数。** 理由:普通物理/程度判断判错了,是世界模型内部的错误,可以后续订正;但放行一个从没有合法路径确立过的新实体,是让玩家断言直接变成了现实,违反了整个项目最上位的权力边界("玩家提交意图,不提交现实"),这不是随机噪音,是把边界本身松动了,性质不同,不能套用"史料容错"的逻辑。
4. **判官之间的分歧本身是有用信号,不是需要压制的噪音。** 三票接近一致通过→直接结算,不必制造悬念;接近一致拒绝→大概率是真编造(编造类分歧通常很小);**明显分裂→说明这件事本身有多种合理走向,恰好是"这里该被局部 Collapse"的动态信号**,不需要工程师提前手工登记地址。但分裂之后由谁来收紧这个约束空间,依然不能是"听玩家的"——`dependencySource` 不允许 `player-claim` 这条线在这个新场景下继续成立,resolver 要看什么更一致/更有戏,不能看玩家想要什么。

## 8. 两阶段的接缝:大致已解,剩下的是检索工程问题

`plausibility-judge-spike` 里"信息不足"案例(模型正确说"桌子多重、玩家力量都没给,无法判断",不编数字)+ 第 6 节 `reachability-inference-spike` 的结果合起来,基本回答了"Adjudicator 怎么区分'缺一个已知但没提的属性'和'缺一个真正从未确定的属性'"这个原本悬而未决的问题:

- Adjudicator 拿到的不该是人工策展的一小段语境,而应该是**检索出的、与本次 Attempt 涉及实体相关的完整命题集合**(第 6 节已证明,给足相关命题后,模型在这上面做单跳/多跳推理、拒绝错误推导都是可信的)。
- 用这个命题集合去裁决 Attempt:能推出结论就直接结算;**如果给足了检索到的相关命题之后,模型依然诚实地说"信息不足"——这时候的"信息不足"才是可信的、该拿去触发 Collapse 流水线的信号**,不是 Adjudicator 偷懒或没被喂饱语境的假阳性。
- 新事实经第 7 节的编剧+陪审团流水线进入真相文档库后,回来完成裁决。

**这条接缝里剩下的唯一开放问题,不再是"Adjudicator 怎么区分两种缺失"(这个已经有了可信的判据:喂饱相关命题之后是否依然信息不足),而是纯粹的检索工程问题:"喂饱相关命题"这一步,在语料库变大之后能不能真的把对的那几条命题捞出来。** 这需要接入真实检索层单独验证,不是靠改 prompt 或者继续测模型推理能力能回答的。

## 9. 术语修正:我们要的是"结构但非形式化",不是"不结构化"

edwin 纠正:前面几节里"结构化 vs 自然语言"这组对立用词不准。真相文档库**不是没有结构**,它有结构,只是这层结构是**文档格式约定**,不是**类型 schema 约束**。具体来说,结构体现在:

1. 叙事命题列表;
2. 主谓结构(自然语言句子本身就带语法结构,不是随意词袋);
3. 列表有顺序(对应 Height/时间顺序);
4. 平铺(不嵌套);
5. 一行一个命题;
6. 相关的命题放同一份文档(用实体名字/世界 namespace 做定位,不是用属性字段)。

**我们放弃的,只是"卡字段、kv、类型、枚举值域"这一层——形式化,不是结构本身。**

这个区分带来一个具体的工程收益,而且这次讨论里已经有现成的反例证据:**类型化 schema 的校验是原子性的,一个字段错了,整份输出作废。** `semantic-intent-spike` 的 gun-induction 案例里,OLD 臂(结构化方案)只因为 `unresolvedDependencies[0].slot` 引用了一个不存在的 slot,整个输出被判 `MODEL_INVALID_SCHEMA` 全部作废——即使其余字段大概率是对的。而一行一个命题、平铺、非嵌套的文档,**一条命题错了,顶多这一行被陪审团否决或订正,不会连累同一份文档里其它命题——非原子性失败**。这正是第 1 节"错误可承受、能被纠错机制圆回来"这条判断,在文档格式层面能够真正落地的具体机制,不是一句原则宣言。

**实体名字/地址的职责因此可以缩得很窄,不是不要它:** 它唯一的活是身份稳定("一号门"这次和上次说的是不是同一个东西)和检索定位(用它做过滤键,把相关命题捞到一起),不承担任何属性建模的工作。真相文档库的骨架大致是:

```
namespace(世界)
  → 实体名字(身份 + 检索键,不是属性表)
    → 一份按 Height/时间排序的自然语言命题列表(平铺,一行一个,主谓结构)
```

命题内容本身完全不形式化;结构只存在于"怎么组织、怎么定位、怎么排序"这个格式层。
