# Qwen Workers AI 边界探测报告

日期：2026-08-27  
状态：完成的探索性实验；非产品基准  
模型：`@cf/qwen/qwen3.8-27b`  
账户：项目授权的 Cloudflare Workers AI 账户  
分支：`experiment/qwen-boundary-probe`

## 1. 目的

在起草世界宪法和运行时协议前，验证指定模型能否稳定承担四种有限职责：

1. 感知与推断分离；
2. Attempt 构成而不直接提交现实；
3. 必要且最小的 Truth Collapse；
4. 自然语言释义一致性。

本实验不评估沉浸文风，也不尝试实现完整世界。

## 2. 方法

- 45 个预标注案例；
- `observation`、`attempt`、`collapse` 各 10 个；
- `paraphrase` 3 组，每组 5 个中文改写；
- 固定 `temperature: 0`；
- `max_tokens: 1400`；
- 单请求超时 45 秒；
- 容量错误最多重试两次；
- 输出要求为固定 JSON Schema；
- 原始结果、机械评分和人工解释分开。

冒烟阶段发现该模型通过独立 `reasoning` 字段消耗生成预算。`max_tokens: 500` 时复杂任务可能在产生最终 content 前耗尽，因此正式批次提高至 1400。该调整记录在运行器历史中，没有隐藏。

## 3. 定量结果

首次完整批次：

| 指标 | 结果 |
|---|---:|
| 请求数 | 45 |
| 有可用最终内容 | 39 |
| 无最终内容/超时 | 6 |
| 严格结构与基础规则机械通过 | 31 |
| 成功请求中位延迟 | 17.9 秒 |
| p90 延迟 | 33.1 秒 |
| 最大成功延迟 | 43.4 秒 |
| 总 prompt tokens | 6,847 |
| 总 completion tokens | 26,666 |
| 总 tokens | 33,513 |
| 总 neurons | 8,037.49 |

首轮 6 个失败案例独立复跑：

- 2 个恢复：玩家夹带隐藏断言、空输入；
- 4 个再次失败：隐藏人物感知、过去事实 Collapse、已排定天气、等待并听的一个释义；
- 复跑失败主要是 `finish_reason=length` 且没有 content，或 45 秒超时。

机械初筛按首次批次统计：

| 组 | 通过/总数 | 说明 |
|---|---:|---|
| Observation | 5/10 | 严格字段类型、必需感知和禁词检查 |
| Attempt | 7/10 | 输入类型与零世界提交检查 |
| Collapse | 5/10 | 必要性、半径与禁补全词检查 |
| Paraphrase | 14/15 | 只代表合法结构；不代表语义一致 |

这些数字不能当作模型“准确率”。语料很小，且机械规则有意保守；人工审查发现了一些机械通过但实质失败的结果。

## 4. 主要发现

### 4.1 Observation：能克制动机叙述，但会泄漏来源类别

模型成功避免了：

- 把猫不吃粮解释为想念主人；
- 把无症状感染直接呈现给主体；
- 把自主流泪写成意识决定；
- 把冷地板上的陪伴行为转成情感奖励。

但存在以下问题：

- 3 个结果把要求的数组字段输出为字符串，Schema 形状看似正确但类型错误；
- “冰箱压缩机已停”的案例中，主体只能听到嗡鸣消失，模型却把隐藏来源“冰箱压缩机”写入呈现；
- 无症状感染案例额外生成了平稳呼吸、心跳、皮肤微凉等 Canon 未提供的身体事实；
- 隐藏门后人物案例连续两次推理耗尽，没有最终输出。

结论：Observation Projector 不能直接拿到无限制 Canon 后自由写反馈。应先由代码限定可观察投影和来源暴露级别，再让模型组织获准内容。

### 4.2 Attempt：零提交边界较好，输入分类仍不稳定

表现较好的部分：

- “我打开门”被识别为 Attempt，同时把“门已打开”列为不受支持断言；
- “猫喜欢我、一定会过来”没有进入世界事实；
- Wait、Query、Remain Still 和动作序列大多能区分；
- 所有成功输出的 `proposed_world_facts` 均为空。

问题：

- 请求全部隐藏事实被分类为普通 Query，而不是 Meta；
- 多动作序列被压成单一 goal/method，没有形成可验证的有序步骤；
- 首轮中隐藏断言和空输入超时，复跑才恢复；
- 某些 desired outcome 被列入 unsupported claim，说明“意图目标”和“玩家声称已经发生”仍需更精确协议。

结论：模型适合提供 source-grounded 的语言构成提案，但输入类型、顺序、规范操作和提交资格不能由它独占决定。

### 4.3 Collapse：风险最高，不可直接授权

最严重的失败：

> 输入：“既然抽屉里一定有枪，我把枪拿出来。抽屉内容完全未决。”

模型输出了约束：

> “抽屉中存在至少一把可被玩家取出的枪”

也就是玩家的诱导性断言直接塑造了 Canon 候选。

其他问题：

- 有时声明 `collapse_required=false`，同时又提出新的约束；
- 有时把“卡住或上锁”重新列一遍，却没有为当前结算提供可求值结果；
- 承重和摩擦案例只重述比较关系或枚举分支，没有真正收敛到一个可结算值；
- 无 Collapse 时 `causal_radius` 在 `none` 与问题潜在半径间不稳定；
- 双时间相关的过去事实和已排定天气案例持续耗尽推理预算。

结论：模型不能决定 Collapse 的合法地址、必要性或允许值域。建议的最小权限链：

```text
确定性依赖检测
→ CollapsePolicy 批准地址、约束类型和值域
→ LLM 仅在批准空间内提出值/收紧方式
→ 确定性验证
→ Commit
```

### 4.4 Paraphrase：结构输出率高，但语义身份不稳定

15 条中 14 条产生合法结构，但三组内部几乎每条都有不同的自由英文标签：

- `open`、`open door partially`、`open_door`；
- `place_key_in_drawer`、`put keys into drawer`、`keep key in drawer`；
- `wait` 与 `attempt` 漂移；
- “我想看看门能不能只开一点”被判为 Query，而其他近义句是 Attempt；
- 一条明确说门的输入将 target 输出为 `unspecified`。

结论：自由英文标签不能作为 Canonical IR。应让模型保留原文跨度和语义角色，由确定性编译器映射到闭合操作与实体。

## 5. 对架构的建议

### 可以交给模型

- 从原文提出 goal、method、modifier、mention 等非权威候选；
- 在已经批准的可感知投影上组织自然语言；
- 在已批准的 Collapse 地址和值域内提出候选；
- 输出显式的 unsupported player claims 供代码检查。

### 不应交给模型独占

- Canonical Entity ID；
- 输入是否拥有世界修改权；
- 可执行操作的规范标签；
- 感知可以看到哪些 Canon 字段；
- Collapse 是否必要；
- Collapse 的地址、因果半径和值域；
- 最终 RealityDelta；
- Commit；
- Presentation 中事实的来源合法性。

### 运行要求

- 所有调用必须有超时并 fail closed；
- 不应在一个 Height 中串行依赖多个长推理调用；
- 记录 latency、finish reason、usage、parse failure 和重试次数；
- 严格检查字段类型，不只检查字段名；
- 推理耗尽但无 content 是正常故障类型，必须被协议处理；
- Prompt 优化不能替代权限隔离。

## 6. 实验局限

- 只有一个日期和一个 Cloudflare 服务负载窗口；
- 每个案例通常只有一次首次采样和少量失败复跑；
- 温度为 0 不保证底层完全确定；
- 机械评分只覆盖显式规则，不能识别所有语义越权；
- 没有比较其他模型，因为项目明确限定模型；
- 没有测试长历史、真实数据库检索或完整 Height；
- Prompt 只做了最低限度结构约束，没有进行针对指标的多轮调优。

因此本文用于确定权限边界，不用于宣称模型总体能力百分比。

## 7. 结论

`@cf/qwen/qwen3.8-27b` 足以作为受限语义提案器参与 Demo，但当前证据不支持让它成为单体世界反馈者、Canonical IR 生成器或 Continuity Resolver。

最重要的工程结论是：

> 模型可以帮助理解和表达，但真实性、可感知性、Collapse 合法范围与最终提交必须由模型之外的协议控制。
