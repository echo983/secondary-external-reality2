# 结构性缺口补全 2026-08-29

俯瞰全局后确认的三处结构性缺口(跨轮索引竞态、无法查看世界当前记忆、玩家端错误处理粗糙),按建议逐一实现并部署验证。第四条(同一世界并发提交无锁保护)按之前的评估维持不做——现在的场景就是一人独占一个世界,加锁的复杂度和这个低概率风险不成比例。

## 1. 跨轮索引竞态:在每轮结束前主动等索引确认完成

`docs/collapse-indexing-race-findings-2026-08-29.md` 修的是同一轮内的竞态(提交后不重新查库,直接用内存里已有的记录)。但这不能解决跨轮的版本——上一轮最后一次提交如果索引还没跟上,玩家下一轮的 RETRIEVE 依然可能读不到。

新增 `waitForIndexing`:在 `processAttempt` 每一个可能提交过东西的返回点(两处提前边界返回 + 最终返回)之前,收集这一轮所有提交过的条目 id,轮询直到它们全部变成 `completed`(或 `error`)才真正把响应交给玩家。玩家在收到这次反馈之前没法发下一轮输入,所以只要这一步做到,下一轮开始时索引必然已经完成。

代价是真实存在的:实测里这一步单独又加了 30-50 秒。这是有意接受的权衡——正确性问题(真相文档库自相矛盾)比再多等几十秒更重要,而且这个等待只发生在"这一轮真的写了新东西"的情况下,纯观察、边界拒绝这类不写东西的轮次不受影响。

## 2. 世界记忆调试视图

新增 `GET /w/<worldId>/facts`,返回这个世界当前全部已提交命题,按 Height 排序。网页上加了"世界记忆"按钮,点开直接看表格,不用再像排查 H6/H7 矛盾那次一样现写脚本去 AI Search 原始接口里挖。

## 3. 玩家端错误处理

之前调用彻底失败时,网页会把原始 JSON 错误堆栈直接塞进对话气泡展示给玩家。现在改成:检测到这是一次真实的调用失败(有 `error` 字段、没有 `narration`)时,展示"这次结算失败了……你的输入没有生效，世界状态没有变化，可以直接重试"这类清楚、可操作的话,不再把技术细节甩给玩家。

## 部署验证中意外发现:一次真实的瞬时网络故障,和这次改动无关

第一次跑完整场景验证时,第 3、4 轮客户端直接报 `TypeError: fetch failed`,一度怀疑是新加的等索引逻辑把总耗时推过了某个平台硬限制导致连接被掐断。查了 Cloudflare 官方文档确认:**HTTP 请求只要客户端保持连接就没有硬性墙钟时长限制**,不是平台层限制。直接重试了一遍同样的两个请求(带更长的 curl 超时),两次都干净地成功了(202 秒、89 秒,`INDEX_WAIT` 里 `allIndexed: true`),证实是本地测试脚本这一层的瞬时网络故障——`test/run-scenario.mjs` 的 `fetch` 调用一直没有重试逻辑(Worker 自己的出站调用早就有了,本地测试脚本这层一直没补),顺手给它也加上了重试,以后不会再被这种偶发故障中断整个场景验证。

## 验证

新世界 `structuralfix1` 跑完整 5 轮场景,最终 19 条记录全部 `completed`、逻辑自洽——毛毯厚度、门缝宽度、塞入后两侧外露、剩余空隙,前后呼应,没有出现类似 H6/H7 那种矛盾。
