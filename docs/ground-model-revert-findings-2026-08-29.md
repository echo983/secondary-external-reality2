# GROUND 模型分级切换的真实回归,已回退 2026-08-29

真人测试第二轮抓到的问题:同一次会话里,"看看周围"第一次正常通过,"再看看周围"第二次被 GROUND 判定成"周围"是个不存在的实体,直接边界拒绝。两次表达几乎一样,结果不一样。

## 根因:8 月 29 日给 GROUND 换的模型(`qwen3-30b-a3b-fp8`),在"模糊空间指代"这类输入上不稳定

`docs/model-tier-spike-findings-2026-08-29.md` 那次 A/B 用的 8 条测试案例,没有一条是"看看周围""环顾四周"这种不点名具体物件、纯粹泛指周边环境的表达——全是"看看毛毯""量一下门缝"这种明确指向已知实体的案例。真人测试把这个盲区测出来了。

直接对比验证(同一句话,温度 0,连续 3 次调用):

```
基线模型 qwen3.8-27b：
  "看看周围"    -> unbound:[] / unbound:[] / unbound:[]     一致，都对
  "再看看周围"  -> unbound:[] / unbound:[] / unbound:[]     一致，都对

换上的 qwen3-30b-a3b-fp8：
  "看看周围"    -> unbound:["周围"] / unbound:[] / unbound:[]        不一致，一次错
  "再看看周围"  -> unbound:["周围"] / (解析失败) / unbound:[]        不一致，一次错、一次连输出都解析不出来
```

基线模型在这类输入上完全稳定,新模型会飘——这不是"换了个可以接受的答案",是真实的正确性回归,只是当初的测试集没有覆盖到能暴露它的那类输入。

## 处理:GROUND 换回基线模型

`docs/model-tier-spike-findings-2026-08-29.md` 记录的三个角色分级,GROUND 那部分现在撤销——37% 的延迟收益不值得用这种不稳定性去换,尤其"看看周围"这种表达是玩家最普通、最高频会说的话之一。CLASSIFY 和 REACHABILITY_CLASSIFIER 换成 `llama-3.1-8b-instruct-fast` 那部分不受影响,继续沿用(这次问题只在 GROUND 上,那两个角色没有类似证据)。

部署后直接对着真实 `/attempt` 重复三次"再看看周围"验证,三次都正确通过,和基线模型的稳定表现一致。

## 这次的教训,记下来避免下次重复犯

**8 条测试案例覆盖的是"正确处理明确实体"这一类,完全没有覆盖"正确识别模糊指代/不该被当成缺失实体"这一类——这是两种不同的能力,一个模型在前者上打满分,不代表在后者上也稳。** 以后再给某个角色换模型,测试集要包含这两类边界情况,不能只测"这个应该被正确绑定"的正例,还要测"这个不该被误判成缺失实体"的反例——尤其是原本已经验证过、玩家会高频说的自然表达(比如这一路 session 里反复用的"看看四周""环顾四周"这类)。
