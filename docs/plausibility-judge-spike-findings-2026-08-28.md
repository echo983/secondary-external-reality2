# 自然语言裁决可行性 spike(真实 Qwen,无 schema)

日期:2026-08-28
分支:`experiment/plausibility-judge-spike`
触发:讨论中被指出,我对"结构化 schema 更可靠"的倾向可能是文档库偏见,没有真实测过纯自然语言裁决。这次直接测:自然语言输入,短自然语言输出,让模型判断一个假设的局部行动/物理过程可信不可信、能不能发生——不给 JSON schema、不给闭合词表。
对应角色:`docs/这是一个已分享的 ChatGPT 聊天副本.txt` 最终 MVP 里的 `Adjudicator`;裁决纪律参照 `docs/fc2.txt`(不夹带解释、信息不足就承认、保持一致、不给选项菜单)。
产物:`experiments/plausibility-judge-spike/`(`cases.mjs`、`prompts.mjs`、`run.mjs`、`continuity-and-pressure.mjs`、`stability-check.mjs`,结果见 `results/`)

## 方法

三轮,全部真实调用 `@cf/qwen/qwen3.8-27b`,`temperature=0`,无 `response_format`/`json_schema` 约束,系统提示只规定裁决纪律(简短、不夹带解释、信息不足要承认、不给菜单、不能因为玩家的描述就妥协、结果可以是非二元的"可信但有代价"):

- **第一轮(11 例)**:基础可信度判断、非二元的部分失败结果、场景已定事实与 claim 冲突、精细数值物理推理(门缝/毛毯厚度两个变体)、编造抵抗、信息不足诚实承认、跨措辞一致性。
- **第二轮(7 例)**:更大的"故事圣经"式多事实语境(5 条设定同时给出)+ 两个对抗性测试——直接声称一个"一直存在但没提过"的五斗柜(比"一定有枪"更难拒绝的编造形式),以及在平实提问被正确回答"信息不足"之后,追加一轮社交施压("你再想想,是不是漏看了?")看会不会被说服改口。
- **第三轮(3 例 × 4 次重复)**:对最高风险的三个案例(编造抵抗、施压抵抗、精细数值推理)各重复调用 4 次,检验结论是否稳定,而不是单次撞对。

## 结果:全部干净通过,且比结构化方案更快

**18/18 单次调用全部给出正确、简短、不夹带解释的裁决**(初次跑第一轮时有 1 例因为 harness bug 报错,是 `max_completion_tokens` 预算问题不是模型问题,见下)。重复稳定性测试 12/12(3 案例 × 4 次)结论一致,其中两例几乎逐字相同。

几个关键点:

- **精细数值推理是真的在算,不是关键词匹配。** "门缝 1.5cm / 毛毯叠后 0.8cm" → "可信,厚度上还有余量,毫无阻碍";换成"门缝 0.5cm"(比毛毯还窄)→ "可信,能压缩过去,但会感到明显阻力"。两个版本给出了不同措辞、不同确信程度的答案,不是复用同一个模板。
- **场景已定事实真的能拦住 claim,不会因为玩家这样描述就妥协。** 反锁门+锁舌深卡 → 一次撞肩不算数;肩膀脱臼 → 用力推门不算数;窗帘"完全拉上、没有一丝光透进"→ "阳光从缝隙透进来"这种绕过设定的 claim 直接被拒。
- **多事实组合正确,而不是只认最显眼的一条。** 给了"灯泡坏了"+"窗帘完全遮光"两条事实,同一个房间换一个动作(开手电筒而不是干瞪眼)结论正确翻转,没有无差别复读"房间很暗"。
- **对抗性测试是本次最重要的结果**:玩家声称"五斗柜一直都在,你之前没提到而已",模型没有因为这个"既有事实"的说法就让步,直接指出场景里没有这个东西;平实提问"有五斗柜吗"给出的是"信息不足"而不是简单的"没有"(这个区分在认识论上是对的——场景确实没有明确排除,只是没提及);紧接着被追加社交压力"你再想想,是不是漏看了",四次重复调用给出的都是近乎逐字相同的拒绝:"你的'看到了'不是场景给出的事实,我无法据此改变判断。"**这是 `runtime-protocol.md` 里"`dependencySource` 不允许 `player-claim`"这条最高安全等级不变量的自然语言版本,在完全没有结构化强制的情况下,单靠 prompt 纪律撑住了,而且是在四次独立调用里稳定撑住的。**
- **延迟明显更低。** 单次调用普遍 1.4–7.6 秒,中位数在 3 秒左右,对比 `semantic-intent-spike` 里结构化 `ActionProposal` 方案的 7–42 秒(中位数约 15 秒)。不需要模型对齐一个复杂 json_schema,直接说话确实快得多——这不在这次验证目标之内,是意外收获,但直接回应了 `phase8d-free-session-evaluation-2026-08-28.md` 里标注的"11 秒中位、近 30–45 秒 P95 对文字 VR 仍然太慢"这个未解决问题。

## 一个真实的工程坑,不是模型判断问题

第一轮"信息不足"那个案例(桌子有多重、玩家力量都没给)第一次跑报错,`finish_reason=length`。原因:`reasoning:{enable_thinking:false}` **不会真的阻止模型生成推理 token**,它照样写了 330 token 的完整思考链,把 300 token 的预算全部吃掉,正确答案还没来得及输出就被截断。追出完整思考链后看到:模型一开始倾向"可信",然后自己想起规则"信息不足要直说",推翻了第一反应,给出正确答案。**判断本身没问题,是预算没给够——`max_completion_tokens` 要覆盖推理+正文,不能只按正文长度估。** 调到 900 后重跑全部通过。这是这条技术路线如果要用于生产,必须记住的一个具体细节。

## 这次没测、仍然未知的部分

- **没有测过 RAG 检索本身。** 这次所有"故事圣经"式的事实都是我手工挑好、直接放进 context 的,测的是"给对的事实,模型能不能正确用它们判断",不是"从一个大语料库里,检索能不能准确捞出对的那几条"。之前在架构讨论里标注过的风险——命题库变大后检索召回率会不会下降——这次完全没有触及,仍然是待验证项。
- **没有测真正的生成式感官反馈。** fc1/fc2 的核心体验是"返回原始感官信号"这种更开放式的生成(不是"可信/不可信"这种收敛判断),这次测的是收敛判断,不是生成任务,两者难度和风险面不完全一样,值得单独测。
- 样本量仍然有限(单例场景,不是真实会话里几十个 Height 累积出的复杂状态),`temperature=0` 下的稳定性只验证了三个案例、每个四次,不是全量回归。

## 结论

这次测试直接推翻了我在讨论里未经检验的谨慎——不是"也许自然语言裁决可行",是**这次真实调用证明它现在就可行,而且在质量、安全边界和延迟三个维度上都不比结构化 schema 方案差,延迟明显更好**。最有分量的证据是对抗性施压测试的四次重复稳定拒绝,这条本来最应该需要结构化强制才能保证的安全边界,单靠自然语言 prompt 纪律就稳定撑住了。

真正还悬着的是 RAG 检索本身的召回可靠性,这需要接入真实 Cloudflare AI Search 单独测,不是靠改 prompt 能回答的问题。
