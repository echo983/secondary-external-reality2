# MVP 设计文档编写计划修订 v0.2

状态：计划草案  
日期：2026-08-27  
上位计划：`MVP-design-documents-plan-v0.1.md`  
参考材料：`fc1.txt`、`fc2.txt`、`世界反馈者手册.md`

## 1. 修订结论

原计划的四份核心文档及其先后顺序保持不变：

```text
demo-goals.md
→ world-constitution.md
→ runtime-protocol.md
→ adjudication-cases.md
```

三份新增材料是人工实验记录和 LLM 经验总结，只作为参考，不自动成为项目决定。它们带来的主要变化是：在正式起草四份规范文档前增加一项非规范性的“实验参考综合”，并要求四份文档显式处理身体、感知和主体推断。

修订后的完整顺序为：

```text
旧项目遗产提取
→ 实验参考综合（非规范性）
→ demo-goals.md
→ world-constitution.md
→ runtime-protocol.md
→ adjudication-cases.md
→ 交叉审查并冻结 MVP 设计基线
```

本修订与 v0.1 冲突时，以本修订为准；未涉及的部分继续按 v0.1 执行。

## 2. 新增前置产物：实验参考综合

新增工作文档：

```text
docs/reference-experiment-findings.md
```

该文档是非规范性研究记录，不是第五份上位设计规范。其目的包括：

- 记录两次实验中实际出现的现象；
- 区分实验现象、主体解释、反馈者解释和事后总结；
- 提炼值得考虑的机制；
- 保存替代解释、反例和内部矛盾；
- 明确每项发现的采纳状态；
- 防止参考材料中的强措辞未经决策进入世界宪法。

每项发现使用统一格式：

```text
观察：实验中实际发生了什么
候选解释：它可能说明什么
替代解释：还可能由什么造成
设计启示：值得考虑的机制
当前决定：采纳 / 部分采纳 / 暂缓 / 拒绝 / 未决
影响文档：目标 / 宪法 / 协议 / 案例
```

重点评估但不预设采纳：

- 身体作为受限感知与控制接口；
- `ControlGranularity`、自主身体系统和生理压力；
- `Sensation`、`Observation`、`Inference`、`Belief` 的分层；
- L0–L4 感知分辨率作为设计检查工具的价值与边界；
- `alias`、`define` 与主体概念接地；
- “不许在乎”作为反剧情偏转原则的适用边界；
- 黑名单机制的认识论与叙事控制风险；
- 完整预生成世界与最小 Collapse 原则的冲突；
- 每 Attempt 固定推进时钟与双时间模型的冲突；
- “每次附赠一项信息”可能造成的泄漏和暗示。

只有被后续四份文档明确吸收的结论才具有约束力。

## 3. 对 `demo-goals.md` 的调整

### 3.1 增加体验路线决策

首版必须明确选择或组合以下体验形态：

1. 人类日常身体与小型生活空间；
2. 未知非人身体与概念接地；
3. 人类日常主 Demo，另设非人身体内部技术实验。

当前建议优先评估第 3 种，但在 `demo-goals.md` 经项目所有者审查前不视为决定。

### 3.2 增加候选体验目标

除 v0.1 已列目标外，增加以下候选目标：

> 玩家应能区分“角色感知到了什么”和“角色据此推断了什么”。

该目标需要落实为可观察的验收标准，不能只作为文案风格要求。

### 3.3 保持场景约束

实验材料不授权首版直接扩张为完整认知发育、未知物种或生存模拟。非人身体如果进入计划，默认作为独立技术实验，不自动成为面向普通用户的主 Demo。

## 4. 对 `world-constitution.md` 的调整

### 4.1 增加认识分层

宪法需要显式区分：

```text
Reality
→ Sensation
→ Observation
→ Inference
→ Belief
→ Memory
```

至少审议并冻结以下原则：

- 主体推断不得自动晋升为 Canon；
- 系统因果解释不得伪装成主体的直接感知；
- 旧观察可以被重新解释，但不得被静默改写；
- 后续证据可以修正 Belief，不得反向篡改当时取得的 Observation；
- 同一事实可以被不同主体以不同证据路径获知或误解。

### 4.2 增加具身边界

需要审议：

- 意识不能直接控制全部身体状态；
- 反射、自主生理和身体自动能力是合法的 RealityDelta 来源；
- 身体机制既可能帮助主体，也可能妨碍主体；
- 身体机制不得为了保护或惩罚玩家临时改变。

### 4.3 将“不许在乎”改写为可执行原则

不直接采用手册的绝对措辞。候选规范表述为：

> 世界裁决不得为了奖励、惩罚、引导或制造戏剧效果而偏转因果结果。所有主体和过程应依据已提交状态、目标、机制与约束行动。

同时区分：

- NPC 可以拥有目标、价值与偏好；
- 世界内核不得拥有“希望玩家看到某段剧情”的偏好；
- 产品层仍应关心安全、可理解性、调试能力和体验质量。

### 4.4 不预先采纳的手册规则

以下规则只能作为待评估参考，不能直接写入宪法：

- `L4 永不`；
- 全局词汇黑名单；
- 反馈者必须持有完整世界模型；
- 每回合必须额外提供一项玩家没问的信息；
- 死亡关闭时将致命代价改成信息；
- 世界反馈者必须在所有意义上“无意图”。

## 5. 对 `runtime-protocol.md` 的调整

### 5.1 行动链与体验链并列

协议必须同时定义两条闭环：

```text
行动链：
Attempt
→ Adjudication
→ RealityDelta
→ Commit

体验链：
Canonical Reality
→ Embodiment / Perception Filter
→ Sensation
→ Observation
→ Epistemic Update
→ Approved Presentation
```

两条链在 World Height 中汇合。体验链不得被降格为提交之后的自由文本润色。

### 5.2 评估最小具身结构

运行时设计阶段评估但不保证首版全部实现：

```text
EmbodimentProfile
- controllable_capabilities
- control_granularity
- sensory_channels
- sensory_bandwidth
- autonomous_systems
- pressures
- physiological_limits
```

其中最值得首版保留设计位置的是：

- `ControlGranularity`；
- `SensoryChannel`；
- `AutonomousBodySystem`；
- `Pressure`。

完整概念接地、`alias()` 和 `define()` 独立 API 默认暂缓。自然语言仍是玩家主接口；未来可以将命名和行为封装解释为 `Epistemic Operation`。

### 5.3 Observation 需要来源与分辨率

候选字段包括：

```text
Observation
- observer
- modality
- content
- source_fact_ids
- source_event_ids
- spatial_scope
- resolution
- salience
- observed_at_height
```

核心要求是能审计一段反馈来自哪些已提交事实，以及 Renderer 是否越权增加了因果解释。

### 5.4 时间模型保持原决定

不采用“每条 Attempt 固定推进一格”的人工跑局方法。继续坚持：

- Height 是逻辑和事务顺序；
- World Time 是世界内实际时间；
- 不同 Attempt 可以消耗不同时间；
- Query 或元操作未必推进显著 World Time；
- 后台事件由 Process Schedule 和 World Time 到期触发；
- 不为了节奏或避免无聊而人为推进事件。

持续底噪及其停止可以作为很好的 Autonomous Process/Observation 案例，但不能成为强制叙事技巧。

### 5.5 世界无需完整预生成

手册要求人工反馈者画出完整地图，是维持人工跑局一致性的办法，不是运行时原则。新系统继续采用：

```text
已提交 Canon
+ 未决约束
+ 持续过程
+ 当前需要时的最小 Collapse
```

必须充分约束当前因果范围和可达边界，但不要求预生成玩家无法到达的全部空间。

## 6. 对 `adjudication-cases.md` 的调整

### 6.1 两类正确性

每个相关案例同时检查：

- **世界正确性**：状态、因果、时间、Collapse、Commit 和 Replay 是否正确；
- **体验正确性**：感知范围、身体反馈、主体推断和呈现权限是否正确。

世界状态正确但反馈越权，仍然判定为失败。

### 6.2 从实验材料新增的案例候选

#### 身体与自主过程

- 腿麻时尝试站起，只产生物理支持范围内的结果；
- 强光触发流泪，不占用主动 Attempt；
- 分布式肢体控制返回强度分布而非纯失败；
- 自动吸附、伪装或缩手由刺激触发；
- 身体自动系统可能帮助，也可能暴露主体；
- 高代谢压力在主体专注探索时仍然推进。

#### 感知与推断

- 坐在冰冷地面陪伴 NPC，首先收到共同发生的身体感觉；
- “猫没有吃东西”不能被 Renderer 写成“猫在等待原主人”；
- “附着物较短”不能被直接写成“说明对象经常移动”；
- 主体对卷帘、猫或自身身份的解释不能进入 Canon；
- 后续证据推翻主体先前解释，但不修改旧 Observation；
- 感觉、推断和客观事实不一致。

#### 概念与命名

- 正常人类识别熟悉类别，无需被迫降到 L1 描述；
- 未知身体使用未接地类别词时，系统不让该词替代事实检查；
- 主体给未知实体建立临时别名；
- 两个主体对同一 Canonical Entity 使用不同别名；
- 后续证据修正或推翻主体分类；
- 行为封装不直接改变外部世界。

#### 独立世界

- 玩家做出善意行为后，NPC 仍依据自身状态行动；
- 后台底噪按过程停止，而非等待玩家发现；
- 玩家等待时独立事件继续发生；
- 玩家忽略事件时，事件仍按原因果链结算；
- Renderer 不得为了引导玩家查看某处而追加暗示；
- 重复同一 Attempt 可能因时间和状态变化产生不同结果，因此不得假设 Attempt 幂等。

## 7. 修订后的实际执行批次

1. 完成旧项目遗产映射工作笔记；
2. 编写 `reference-experiment-findings.md`；
3. 审查每项实验发现的采纳状态；
4. 起草 `demo-goals.md`，首先确认主 Demo 的体验路线；
5. 起草 `world-constitution.md`，冻结现实、具身、感知、推断和权限原则；
6. 起草 `runtime-protocol.md`，定义行动链、体验链和 World Height 事务协议；
7. 迁移旧项目案例并补充实验暴露的具身与体验案例；
8. 完成 `adjudication-cases.md`；
9. 对四份核心文档进行交叉审查；
10. 处理未决问题，将确认版本标记为 `frozen`；
11. 依据冻结基线规划并实现首个纵向切片。

## 8. 修订后的退出条件

除 v0.1 的退出条件外，增加：

- 一份明确标注采纳状态的实验参考综合；
- Demo 体验路线已经由项目所有者确认；
- World Constitution 明确区分 Observation 与 Inference；
- Runtime Protocol 同时定义行动链和体验链；
- 至少一组案例证明世界正确但反馈越权仍会被检测；
- 非人身体、概念接地和独立 `alias/define` API 已被明确决定为首版实现或暂缓，而不是处于隐含状态。

满足这些条件后，本修订与 v0.1 共同构成进入正式编码前的计划基线。
