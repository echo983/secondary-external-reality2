# NARRATE 审计 claim-extractor 重新校准(真实 Qwen)

日期:2026-08-28
分支:`experiment/plausibility-judge-spike`
触发:`docs/narrate-audit-retrofit-findings-2026-08-28.md` 发现审计过严(5 轮里 4 轮误触发,包括拦下一句纯触感描述)。这次重新写 claim-extractor 的判断边界,并按"提示词工程不是一次能调好"的原则,分两步验证——先用固定回归集测校准本身,再跑一遍完整五轮场景确认端到端也成立。
改动:`experiments/pipeline-integration-slice/prompts.mjs`(`CLAIM_EXTRACTOR_SYSTEM_PROMPT` 重写,采用 `docs/proposition-language-spec-v0.1-2026-08-28.md` 的共享命题格式定义,补充明确的反例);新增 `experiments/pipeline-integration-slice/claim-extractor-regression.mjs`(隔离回归测试,不跑整条流水线)。

## 方法

**第一步,隔离回归测试。** 直接复用上一轮已经记录下来的四组(已知命题, NARRATE 草稿)真实数据作为固定测试集——一条是应该被判定"不该拦"的纯触感描述("表面是细密的、短的东西",上一版审计误伤的那条),三条是应该被判定"该拦"的真实越界案例(门缝尺寸区间比较、"填满了整条缝"的隐含尺寸声明、"边缘从两侧露出来"的隐含宽度比较)。每条重复调用 3 次,只测 claim-extractor 这一个环节,不重跑 GROUND/ADJUDICATE 等上游阶段,避免其它环节的变化干扰这次要看的变量。

**第二步,端到端重跑。** 回归测试通过后,把同一个 prompt 改动带回完整流水线,重跑一次和之前完全相同的五轮场景,确认隔离测试的结果在真实上下文里也成立,不是脱离整体环境时才有效。

新 prompt 的改动要点:采用共享的命题格式定义(`BASE_PROPOSITION_RULES`)统一措辞;把"不该挑什么"从一句笼统的"质感/结构描述不算",改成三类具体反例(触感/质地、视觉印象、单纯动作描述,并且明确指出"即使写成'细密的短纤维'这种具体程度也不算");把判断标准收紧成一个单一问题——"这句话是在描述质感/印象,还是在断言两个具体量之间有确定的大小/数量关系,或者某个具体尺寸是多少"。

## 结果:两步都干净通过

**隔离回归测试:12/12 全部正确**(4 条案例 × 3 次重复),包括纯触感描述连续 3 次都没有被误判为需要核查的断言,三条真实越界案例连续 3 次都被正确挑出。

**端到端重跑:5 轮里第一轮(纯触感描述那轮)零误触发**,`extractedClaims` 为空,直接沿用草稿,没有走重写分支——这是上一版审计在同样输入下会误伤的那一轮,这次没有误伤。第二、三、四轮里,凡是隐含未经确立的具体尺寸/数量关系的断言(门缝比指尖宽/比尺子厚、"填满了整条缝"、毛毯边缘从两侧露出暗示的宽度关系),依然全部被正确挑出并触发重写,没有漏判。

## 一个连带发现,还没解决

审计生效之后,第二轮("量一下门缝到底有多宽")重写后的最终反馈变成了"你把尺子边缘贴进门缝……你低头看刻度",**没有给出任何读数**——安全了,但不算令人满意的体验:玩家明确尝试测量一个东西,却什么都没量到。这不是这次校准要解决的问题,是 `docs/pipeline-integration-slice-findings-2026-08-28.md` 里说过、还没修的那个更深的问题——"量一下门缝有多宽"这类以获取具体值为目的的 Attempt,现在被路由进了"这件事能不能发生"的可信度框架,而不是"这个值有没有被确定"的可达性框架,导致它从来不会真的触发 Collapse 去产生一个新的、经过陪审团校验的具体数值。NARRATE 审计这道防线堵住了"编数字"这个安全问题,但没有让系统真的把这个数字定下来——玩家问了一个直接的问题,现在得到的是一个礼貌地不回答。**这进一步说明上游路由问题(而不是下游审计)才是能让这类 Attempt 真正得到满意结果的根本修复点,审计只是安全网,不是完整方案。**

## 结论

审计机制的校准问题解决了,两轮独立验证(隔离回归 + 端到端)都确认了这一点,不是只看一次结果就下结论。下一个该修的是流水线路由问题,而不是继续在审计这一层打磨。
