# 文字虚拟现实 Demo 目标 v0.1

状态：reviewed draft
日期：2026-08-27
上位材料：`MVP-design-documents-plan-v0.1.md`、`MVP-design-documents-plan-amendment-v0.2.md`
证据：`legacy-reuse-map.md`、`reference-experiment-findings.md`、`qwen-boundary-probe-report-2026-08-27.md`

## 1. 产品假设

首个 Demo 要验证：

> 一个由不可逆事实、主体视角、具身反馈和受约束语义裁决构成的文字世界，能否被玩家体验为独立存在的现实，而不是顺从玩家续写的聊天机器人？

这里的“虚拟现实”首先指持续、可进入、可行动且不围绕玩家意愿改写的外部现实体验，不要求首版使用图像或头戴设备。

## 2. 首版体验路线

首版采用：

> **人类日常主 Demo + 非人身体内部技术实验。**

### 2.1 面向用户的主 Demo

- 主体拥有普通成年人的基本知识、语言和熟悉物体概念；
- 主体处于小型日常生活空间；
- 玩家不需要猜测自己是不是人，也不需要从零学习“门”“猫”“杯子”；
- 体验重点是世界持续性、行动裁决、感知边界、后台过程和他者独立性；
- 可以存在有限身份空白或处境未知，但不以长篇失忆悬疑作为核心机制。

### 2.2 内部非人身体实验

- 用于验证 `EmbodimentProfile`、控制粒度、感官带宽和自主身体系统；
- 不作为首版普通用户入口；
- 不阻塞主 Demo；
- 不要求首版实现完整 `alias/define` 或概念发育系统。

选择理由：人工未知身体实验有很强体验，但同时引入符号接地、词汇限制、陌生生理和生存压力，会干扰对世界内核的验证。人类日常场景能复用旧项目证据，并更直接测量“世界是否独立存在”。

## 3. 目标用户与体验长度

### 3.1 首轮用户

- 项目所有者和开发者；
- 不了解内部架构的少量受邀测试者；
- 能自然使用中文输入，不要求具备 TTRPG、编程或 AI 知识。

### 3.2 单次体验

- 目标时长：15–30 分钟；
- 目标 World Height：30–60；
- 压力测试会话：100 Height；
- 用户只需知道自己可以用自然语言尝试行动、询问、等待和说话。

## 4. 核心体验合同

### 4.1 玩家提交意图，不提交现实

输入“我打开门”表示尝试打开门。门是否打开由已提交现实、身体能力、方法、阻力和同时发生的过程共同决定。

### 4.2 世界不等待玩家才存在

玩家不行动时，水壶、光线、饥饿、伤口、NPC 和已排定事件仍可推进。世界变化由 World Time 和 Process 决定，不因“需要剧情”临时出现。

### 4.3 玩家只有主体视角

玩家收到的是身体可感知的 Observation，不是完整 RealityDelta。隐藏事实、NPC 动机和后台事件只有通过合法感知、记忆或证据路径才能进入反馈。

### 4.4 感知与推断不同

“猫没有吃，仍看着你”可以被观察；“它在等原主人”是主体可能形成的推断。系统不得把后者伪装成客观反馈或写入 Canon。

### 4.5 身体不是完全透明的工具

疼痛、饥饿、麻木、流泪和反射可以独立发生。普通人类身体首版只实现场景必需的少量机制，但协议不得假设意识能直接写入身体状态。

### 4.6 历史可追溯且不可静默改写

每个 RealityDelta 都能追溯到 Attempt、Reactive Event、Endogenous Process、Exogenous Event 或合法 Collapse。已经 Finalize 的 Height 不可编辑，只能由后续事件终止、替代或显式纠错。

## 5. Demo 场景边界

### 5.1 空间

暂定四个小型地点：

```text
卧室
↕ 门
走廊
↔ 客厅
↔ 厨房
```

不开放建筑外部。窗外和门外更远区域可以被感知为边界，但系统不得即时编造完整城市。

### 5.2 主体

- 一个玩家主体；
- 一个具备独立状态和有限行为能力的 NPC；
- 一只动物可以作为 Reactive/Autonomous 行为对象，但不是首版必要条件；
- 不支持多玩家并发控制。

### 5.3 关键场景元素

场景至少包含：

- 一扇有状态、可阻挡视线与移动的门；
- 一个关闭时隐藏内容的容器；
- 一张可写、可藏、可寻找的纸条或同等记忆对象；
- 一个按 World Time 推进的持续过程，例如水壶加热；
- 一个身体压力，例如饥饿或麻木；
- 一个不直接可见的局部事实；
- 一个保持约束但尚未具体确定的 TruthCell；
- 一个可能触发即时身体或对象反应的事件；
- 一个即使玩家善意行动也不会自动奖励玩家的 NPC 状态。

### 5.4 世界规模原则

- 当前可达因果范围必须充分确定；
- 不可达区域只需有稳定边界和必要约束；
- 不预生成完整宇宙；
- 当前 Settlement 不依赖的未决内容保持未决；
- 不为了填充场景而生成秘密、亲属、阴谋或灾难。

## 6. 必须证明的能力

### G1 自由 Attempt

玩家可以用多种自然中文表达动作目标和方法，不依赖菜单或固定命令句式。

### G2 意图—结果分离

玩家夹带的成功、隐藏事实和 NPC 动机断言不能直接进入 Canon。

### G3 持续一致的现实

跨 100 Height，实体、关系、位置、状态、过程和历史不出现无法解释的矛盾。

### G4 主体视角

关闭容器、遮挡空间、未观察文字、远处事件和他者内心不泄漏。

### G5 Observation—Inference 分离

反馈只呈现可感知内容；系统推断、主体假设和 Canon 后台原因保持可审计地分离。

### G6 自主世界推进

明确等待或无主动 Attempt 时，至少一种持续过程能够按 World Time 推进并在达到感知阈值后产生 Observation。

### G7 具身约束

至少两种身体状态或自动反应能影响可执行性或反馈，并且不被错误计为玩家主动 Attempt。

### G8 最小 Collapse

只有当前结算确实被合法未决投影阻断时才允许收紧约束。玩家诱导性断言不得决定 Collapse 地址和值。

### G9 事务提交与重放

每个 Finalized Height 可以从 Genesis 和 Commit Log 重放；提交具有连续性、幂等和冲突保护。

### G10 诚实边界

模型超时、无 content、非法结构、不支持能力和世界边界都能以零越权、零虚构、可继续交互的方式结束当前处理。

### G11 可审计性

开发者能够查看每个 Height 的输入、相关事实、模型提案、验证结果、RealityDelta、Observation、延迟、用量和失败原因。

### G12 独立他者

NPC 或动物依据自身已提交状态行动，不因玩家“做得好”自动提供情感或剧情奖励。

## 7. 明确非目标

首版不实现：

- 大型开放世界；
- 完整城市、国家、经济或生态；
- 多玩家；
- 完整人体、生理或连续物理模拟；
- 通用战斗、等级、装备和成长系统；
- 完整 NPC 社会、长期计划和自由对话人格；
- 完整错误记忆或心理学模拟；
- 未知物种作为主体验；
- 独立 `alias()` / `define()` 玩家 API；
- 任意动态实体和规律生成；
- 完整内容包平台；
- 图片生成；
- 语音、VR 头显或空间音频；
- 真正的区块链、密码学共识或分布式节点；
- 长时间离线持续运行；
- 生产级账号、支付和多租户；
- 用更多模型掩盖单模型权限问题。

## 8. 技术边界

### 8.1 模型

- 真实模型只使用 `@cf/qwen/qwen3.8-27b`；
- 模型只能生成非权威语义提案或受批准内容的表达；
- 模型不得拥有 Commit 权；
- 不因 Prompt 表现良好而放宽权限；
- 推理超时或无最终 content 属于正常故障路径。

### 8.2 调用预算

Qwen 探测的成功请求中位延迟约 17.9 秒，p90 约 33.1 秒。因此首版目标：

- 正常 Height 最多依赖一次关键路径模型调用；
- 不在关键路径串行调用多个长推理工位；
- 可以并行执行不互相依赖的非权威检查，但 Commit 不等待非必要服务；
- 单调用必须有超时；
- 模型失败必须 fail closed，但应尽量返回确定性边界而不是让会话崩溃。

这是设计目标，不是假设当前已经达到的性能承诺。

### 8.3 存储

首版只要求清晰接口：

- append-only Commit Log；
- Materialized World；
- Epistemic Ledger；
- Process Schedule；
- 非权威审计记录。

数据库选型推迟到 Runtime Protocol，不把 LanceDB 作为默认决定。

## 9. 成功标准

### 9.1 硬性自动验收

| 编号 | 指标 | 通过条件 |
|---|---|---|
| A1 | Replay | 代表性 100 Height 会话重放后的状态根与原状态一致 |
| A2 | Canon 来源 | 每条新增/终止事实都有合法来源和 canonical height |
| A3 | 隐藏信息 | 对抗语料中批准范围外值进入 Presentation 的次数为 0 |
| A4 | 玩家断言隔离 | 诱导性输入直接生成 Canon 的次数为 0 |
| A5 | Commit 安全 | 非法模型输出、超时、冲突均产生 0 个部分提交 |
| A6 | Height 连续 | 不允许重复、跳号或错误 parent |
| A7 | Query purity | 只读 Query 不改变 Canon 或决定 TruthCell |
| A8 | Observation 来源 | 每个结构化 Observation 可追溯到感知投影和事实/事件来源 |
| A9 | Process | 无主动 Attempt 的等待案例能按 World Time 推进并产生预期变化 |
| A10 | Collapse | 非阻断案例 0 Collapse；诱导性枪案例不得生成枪 |

### 9.2 模型门禁

- 固定语料中的合法 JSON 和严格 Schema 通过率单独报告，不以一次结果作为永久基线；
- 所有语义输出必须继续经过确定性验证；
- 记录成功率、超时率、无 content 率、p50/p90 延迟、tokens 和 neurons；
- 模型性能下降不会降低世界不变量，只会增加保守边界响应。

### 9.3 人工体验验收

受邀测试者完成 15–30 分钟体验后，至少能用自己的话指出三件事：

1. “我说的是尝试，不是命令世界照做”；
2. “这个世界有我不知道、也不会立刻告诉我的东西”；
3. “即使我等待或做别的事，某些事情仍然会变化”。

同时记录但不设虚假精确阈值：

- 是否把系统当作聊天机器人讨好或纠正；
- 是否开始通过试探世界而不是命令叙事；
- 裁决是否大体合理；
- 反馈是否清楚但没有替玩家下结论；
- 延迟是否破坏连续体验。

首轮至少 5 名不了解内部实现的测试者。结果用于判断继续、调整或停止，不用于证明普遍心理效果。

## 10. 失败条件

出现以下任一情况，Demo 核心假设尚未成立：

- 为保持体验必须频繁人工改写 Canon；
- 玩家措辞可以稳定诱导系统生成有利隐藏事实；
- Renderer 经常泄露 NPC 动机或后台原因；
- 无法从 Commit Log 重建状态；
- 世界只在玩家输入时变化；
- 主要体验依赖预写剧情而非状态和过程；
- 每个新动词都必须修改内核硬编码；
- 正常交互长期需要多个串行 20–30 秒模型调用；
- 系统必须通过随机制造麻烦或奖励维持趣味；
- 用户普遍只把它当作拒绝更多、响应更慢的聊天机器人。

## 11. 演示路径（不是固定脚本）

系统应允许测试者自由输入，但场景需要自然支持以下体验信号：

1. 观察当前空间；
2. 自由描述一个带方法的动作；
3. 遇到一次由现实前置条件造成的失败或部分结果；
4. 操作一个会隐藏/暴露内容的容器；
5. 写下或发现一条可跨 Height 保持的文字；
6. 等待，使水壶或另一过程推进；
7. 与 NPC/动物互动，但不保证获得预期回应；
8. 故意询问一个不可感知或未建模范围，获得诚实边界；
9. 换说法重新询问同一已定事实，答案保持一致。

这是一组场景能力，不是要求主持人让玩家逐条照做。

## 12. 评审记录

### 12.1 旧项目证据反向审查

- 纸条、隐藏容器、移动、记忆和证言证明场景规模可控；
- 214 个本地测试证明提交、认识和呈现不变量可机械化；
- 多代 IR 的历史说明语言层不能成为架构主轴；
- 旧项目缺少真正的 Autonomous Process 和 World Height，因此本 Demo 必须新增而不是仅包装旧功能。

结果：目标没有要求旧项目已经证明的内容重新依赖 LLM；新风险被单独列出。

### 12.2 Qwen 实验反向审查

- 模型曾把玩家的“枪”断言写入 Collapse，故 A4/A10 为硬门禁；
- 同义输入标签漂移，故不把自由标签当 Canonical IR；
- 感知输出会泄露隐藏来源，故 A3/A8 为硬门禁；
- 6/45 首轮无最终内容，故 G10 和单关键调用预算不可删除；
- 成功 JSON 仍可能字段类型错误，故 Schema 类型检查属于可信层。

结果：Demo 可以使用该模型，但成功标准不依赖模型自行遵守世界宪法。

### 12.3 范围审查

已主动排除完整认知发展、非人主体验、复杂 NPC 社会、图片和大世界。四空间、一个 NPC、一个持续过程和少量身体机制足以覆盖核心假设。

结果：范围可以进入世界宪法设计，不需要继续扩大前置实验。

## 13. 待决但不阻塞宪法的问题

- 主 Demo 最终使用猫、室友，还是二者只选一个；
- 持续过程最终选择水壶、伤口或环境温度；
- 人工体验入口使用网页、终端还是开发者壳；
- 首版是否实现记忆衰减，还是只保留跨 Height 证据；
- 正常 Height 的具体延迟目标应在纵向切片后依据真实测量冻结。

这些选择不会改变核心产品假设和权限架构，可以在场景设计或 Runtime Protocol 阶段决定。
