# Height 优先 + 干净事实写入:核心矛盾修好了,但连带冒出几个新的小问题

日期:2026-08-28
分支:`experiment/plausibility-judge-spike`
触发:`docs/reactive-collapse-findings-2026-08-28.md` 发现的自相矛盾(毛毯同时"在床上"和"在门缝里"),edwin 提议按 Height 大小做冲突仲裁("网飞编剧吃书"式——新覆盖旧,旧的不用改)。
改动:`experiments/shared/proposition-language.mjs`(`BASE_PROPOSITION_RULES` 加入 `[H<n>]` 标注和"冲突时 Height 大的为准"规则,`renderPropositionList` 现在会显示 Height);`experiments/pipeline-integration-slice/prompts.mjs`(ADJUDICATE/JUROR/NARRATE/claim-extractor 全部改用共享的 `renderPropositionList`,并接入这条规则;新增 `FACT_WRITER_SYSTEM_PROMPT`,把裁决结果转写成一条干净的、`FACT_SHAPE_RULES` 合规的已结算命题,而不是直接把裁决原文当命题存)。

## 核心修复:两次独立运行都验证成立

第二次运行里,第 3 轮把毛毯塞进门缝后,COMMIT 写入的是"毛毯被塞在门缝下面，堵住了那道一厘米的缝隙。"——一句干净的已结算状态陈述,不是"结果：xxx —— 可信，xxx"这种裁决日志体。第 4 轮 RETRIEVE 到这条新命题和创世时"blanket-1 现在放在 bed-1 上"这条旧命题同时存在,但流水线正确地(通过最终 COMMIT 记录"毛毯现在是压缩状态，塞在 door-1 门底缝隙里，不再是平铺的样子"可以确认)采用了更新的那条,没有再复现上次"毛毯还在床上"那个自相矛盾。第一次运行里同样的模式也成立。**两次独立运行,矛盾都没有再出现——这不是巧合,是"Height 优先"规则 + "干净事实措辞"这两个改动共同起作用的结果**:光有 Height 优先规则不够(第一版集成切片就是反例,旧命题措辞干净但没有冲突可仲裁;这次修复前的问题恰恰是新命题措辞太脏,冲突认不出来),两个改动缺一个都不成立。

## 连带发现的新问题,篇幅所限只记录、不深挖

- **ADJUDICATE 现在更容易触发 Collapse 了。** 两次运行里,第一轮"看看毛毯摸起来怎么样"这个此前从没触发过 Collapse 的案例,这次都触发了(分别补了"温度适中"和类似的次要属性)。可能是因为 system prompt 现在多了完整的 `BASE_PROPOSITION_RULES`(含 Height/冲突规则的说明),整体变长、变复杂，影响了模型对"信息是否足够"的判断阈值。这是行为漂移,不一定是坏事(补出的事实合理、陪审团也放行了),但值得记一笔，不能假装 prompt 内容变化只影响了目标功能，没有副作用。
- **CLASSIFY 偶尔会把一句纯描述性、没有明确方向的裁决文本("柔软、可以压缩、温度适中")误判成"信息不足"**,即使这句话本身没有表达不确定。这可能是 ADJUDICATE 在温度这类次要属性上给出的裁决风格本来就更像列举清单，不像"可信/不可信"这种明确判断句，导致下游分类器判断犹豫。这次没有深入排查，只记录现象。
- **这条流水线现在链路更深了(NARRATE 审计的每条不可达断言都可能各自触发一次完整的编剧+陪审团流程),两次运行都在某一轮因为 `finish_reason=length` 报错、留下部分提交的状态,不是干净跑完的。** 已经把预算从最初的 900 一路调到了 1800–2200，仍然会偶发触发。这不是这次要解决的问题的一部分，但如实说：这条流水线的调用链已经长到"稳定跑完不报错"本身变成一个需要专门解决的工程问题，不能靠继续加大数字糊弄过去。

## 结论

edwin 提议的"Height 大的为准"这条规则本身是对的、成本低、而且现在有两次独立运行的证据支持它有效，但它能生效高度依赖另一个前提——冲突双方的命题措辞必须清楚到能被认出是在说同一件事，这次顺带修的"干净事实写入"就是在补这个前提，两者是配套的，不是各自独立的两个小修补。

同时这次运行的量级已经足够大，开始暴露一些新的、更琐碎的问题（分类器校准、触发阈值漂移、链路深度带来的稳定性成本）。这些不需要现在逐一深挖——今天这一轮已经从"发现三毫米这个具体 bug"一路走到"验证了一整套 Collapse 触发、真相仲裁、事实措辞的完整机制"，是一个自然的阶段性收尾点。
