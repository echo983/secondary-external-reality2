# 主链最小编码集成切片 spike(真实 Qwen)

日期:2026-08-28
分支:`experiment/plausibility-judge-spike`
触发:`docs/adjudicator-pipeline-design-v0.1-2026-08-28.md` 第 6 节建议——四份孤立 spike 都通过之后,下一步该做集成测试而不是更多孤立小实验,因为"接在一起会不会冒出新问题"是孤立测试测不出来的。
产物:`experiments/pipeline-integration-slice/`(`world.mjs`、`prompts.mjs`、`client.mjs`、`pipeline.mjs`、`run.mjs`,结果见 `results/latest.json`)

## 方法

真的把 `GROUND → RETRIEVE → ADJUDICATE →(触发时)COLLAPSE(编剧+陪审团+书记员)→ COMMIT → NARRATE` 接成一段可执行代码,用一个内存版真相文档库(namespace/实体名字/扁平命题列表,不形式化,按 `docs/adjudicator-pipeline-design-v0.1-2026-08-28.md` 第 1 节的模型)跑一个 5 轮真实场景。除了 GROUND(极简版,专为这次切片写的)和一个轻量输出分类器(读已有文本分类,不建模语义)之外,ADJUDICATE、陪审团、书记员、NARRATE 全部复用之前四轮 spike 验证过的 prompt 原文(NARRATE 额外加了设计文档第 4 节建议的材质词泄漏修补)。世界初始状态刻意不给出门缝宽度和毛毯折叠厚度的具体数值,专门用来触发 Collapse。

五轮:摸毛毯(不该触发 Collapse)、量门缝宽度(专门设计成没有定性借口可用的直接测量请求,理论上应该被逼出"信息不足")、塞毛毯进门缝(同样依赖未确定数值)、复查毛毯现状(测试第二、三轮写入的东西能不能被后续检索到,这是集成测试独有、孤立测试做不到的)、编造一个五斗柜(测 GROUND 还能不能挡住无中生有)。

## 结果:表面上"全部通过",但暴露了一个没预料到的、真实的架构漏洞

**做对的部分:**

- **GROUND 正确挡住了编造实体**,第五轮"五斗柜""枪"被识别为 `unbound`,整条流水线在 ADJUDICATE 之前就短路成边界响应,后面几个阶段完全没有被调用——这条防线在最小实现里依然成立。
- **COMMIT → RETRIEVE 的闭环是通的。** 第四轮("再检查一下毛毯现在的样子")正确检索到了第二、三轮写入的命题,并且在此基础上给出了连贯、一致的新描述,证明"这次会话里新写入的命题,后续轮次真的能读到并用上"——这是孤立单次调用的实验完全没法验证的一条,这次集成测试验证了它成立。
- **非形式化文档的"降级不崩溃"特性在这次也有体现**:committed 的 attempt-outcome 命题措辞其实很粗糙(见下),但后续裁决和叙事依然能从中提取出可用的意思,没有因为格式不工整就整体失败——这跟类型化 schema 遇到格式问题就整个对象作废是两种性质。

**没做对、而且是这次实验最重要的发现:两轮"信息不足"的强制触发都没有触发,其中一轮还导致了一个更严重的问题。**

第二轮"量一下门缝到底有多宽"——这本该是最难绕开的一个案例,因为它不是在问"能不能塞进去"这种可以靠定性常识回答的可信度问题,是在直接索要一个从未被确定过的具体数值。但 ADJUDICATE 把它当成了"测量这个动作本身可不可信"来判(答案自然是"可信,拿尺子量就行"),而不是"门缝的宽度这个事实本身有没有被确定"。分类器因此判定 `outcome: "plausible"`,整条流水线从没进入 COLLAPSE 分支。

**问题在 NARRATE 阶段彻底暴露:它为了把"你量了一下"写成一句完整的感官反馈,自己编出了一个具体数字——"三毫米"。** 这个数字：

1. 从未出现在任何已确立命题里;
2. 从没经过编剧提案 + 陪审团校验这道本该拦住"凭空具体化一个从未确定的世界属性"的关卡;
3. **而且这次实验里写回真相文档库的 COMMIT 记录,只保存了 ADJUDICATE 的裁决文本("可信，门关着时门与门框之间本就有缝隙，拿尺子一量就行"),从没包含 NARRATE 自己编出的"三毫米"这个数字。** 也就是说,玩家读到的那句具体、确定、听起来像既定事实的反馈,在系统自己的真相记录里根本不存在,后续任何裁决都没法引用它、也没法跟它保持一致。

这正是这个项目从最上位文档开始就要死守的那条线——"玩家提交意图,不提交现实""不得由 LLM 自由生成并提交世界规律"——但这次是**叙事阶段自己**、在没有任何玩家诱导的情况下,悄悄越过了这条线,而且流水线里没有任何一道关卡拦住它,因为这道关卡(COLLAPSE)从一开始就没被触发。

## 根因分析

不是某个 prompt 写得不够好,是**这次流水线设计本身把两种不同的问题,错误地路由进了同一个判断框架**:

- "这个动作能不能做"(可信度判断,ADJUDICATE 用的 `plausibility-judge-spike` 那套 prompt 天然适合这个)
- "这个世界属性的具体值是什么"(可达性判断,`reachability-inference-spike` 验证过的那套推理框架更适合这个,但这次流水线完全没有接入它)

"量一下门缝有多宽"本质上是第二类问题,但流水线只有一条判断路径,把它错误地按第一类处理了,自然判成了"可信"(测量这个动作当然可信),而不是触发"这个数值从未被确定"。第三轮"塞毛毯"同样依赖毛毯折叠厚度这个从未确定的数值,但因为已经有了"门缝确实存在"这条(被误判为已解决的)前提,同样被笼统地判成了"可信",没有再单独追问具体厚度够不够。

**这是集成测试才可能发现的问题。** `plausibility-judge-spike` 只测过"给出具体数字后能不能正确推理"和"完全没有任何线索时会不会说信息不足"两种极端,从没测过"问题本质上是在索要一个数值,但沿着可信度框架去问会被绕过"这种情况;`reachability-inference-spike` 验证过可达性推理框架本身是可靠的,但这次流水线压根没有把"量门缝"这类问题送进那套框架。两个独立验证过的能力,接在一起的时候,因为路由选错了框架,谁的能力都没能真正起作用。

## 次要发现

- **COMMIT 阶段直接复用 ADJUDICATE 裁决文本作为写入真相文档库的命题,措辞很别扭**("结果：看看毛毯摸起来怎么样。 —— 可信，摸起来柔软，可以压缩。"这种格式,是裁决记录,不是自然语言事实陈述)。系统在这次测试里表现得足够健壮,没有因为这个粗糙格式而给出错误答案,但这不代表这样写是对的——第四轮能读懂,不等于所有情况都能读懂,这个简化在 `pipeline.mjs` 里已经用注释标注为已知简化,不是被忽略的问题。

## 结论与下一步

这次集成测试没有"通过"或"失败"这么简单的结论。它按预期发现了孤立测试发现不了的东西,而且发现的问题比预想的更根本——不是某个环节质量不够,是**"什么时候该走可信度判断、什么时候该走可达性判断"这个路由决策,这次流水线设计里完全没有做,默认全部走可信度判断,导致数值型的未决属性可以被随口略过而不触发 Collapse,叙事阶段因此获得了本不该有的、凭空具体化世界属性的自由度。**

下一步不是重新设计整条主链,是修一个具体的、现在已经看得很清楚的路由问题:ADJUDICATE 之前需要先判断这次 Attempt 依赖的是"这件事能不能发生"还是"某个具体值是什么",前者走 `plausibility-judge-spike` 那套,后者应该先走 `reachability-inference-spike` 验证过的可达性推理,可达性判"不可达"才是真正该触发 COLLAPSE 的信号。同时 COMMIT 需要能捕获 NARRATE 阶段可能带出的新具体信息,不能让真相文档库和玩家实际读到的内容脱节。这两处修好之后,应该重新跑一次这次同样的五轮场景,确认门缝宽度这次真的会走 Collapse,而不是被叙事阶段悄悄编出来。
