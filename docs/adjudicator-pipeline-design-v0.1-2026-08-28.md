## 1. 真相文档库的数据模型

不追求形式化(类型/字段/枚举值域),但有结构(格式约定)。详细论证见 `architecture-direction-consensus-2026-08-28.md` 第 9 节,这里只给最小实现形状:

```ts
interface Proposition {
  id: string;                 // 稳定引用用，不参与语义
  text: string;                // 自然语言，主谓结构，一行一个命题
  entities: readonly string[]; // 这条命题提到/关联的实体名字，纯粹是检索过滤键，不是属性表
  height: number;               // 在哪个 Height 被确立，用于排序和溯源
  status: "active" | "superseded";
  supersedes?: string;          // 如果这条是订正，指向被订正的 id；订正是新增，不是原地编辑
  source: "genesis" | "observation" | "collapse" | "attempt-outcome"; // 非权威溯源标签，不参与裁决
}
```

- 命名空间(世界)→ 实体名字(身份 + 检索键)→ 一份按 `entities` 索引、按 `height` 排序的扁平命题列表。
- 实体名字的产生走 `世界反馈者手册.md` 5.3 节的 alias 流程:玩家先真实观察,再命名;命名放行后必须在后续叙事里立刻沿用。这部分不需要新设计,手册已经给出完整流程且这次实验(`world-feedback-narration-spike`)验证了它能被正确执行。
- 错误命题不会拖垮整份文档(非原子性失败,`architecture-direction-consensus` 第 9 节有具体反例证据)——订正是追加一条 `supersedes` 记录,不是编辑或删除。这与 `world-constitution.md` §4.4 的"纠错"要求(不得静默编辑)天然一致,不需要额外设计。

## 2. 一次 Attempt 的处理主链

```
OPEN / ACCEPT_INPUT（现有 Height 机制，不变）
  → GROUND     实体绑定，现有确定性 grounding gate，不变
  → RETRIEVE   按 GROUND 阶段确定的实体名字，精确检索所有 status=active 的相关命题
  → ADJUDICATE Adjudicator 用检索到的命题裁决这次 Attempt
      ├─ 能直接裁决（可信/不可信/有条件可信）→ 进入 COMMIT
      ├─ 信息不足，且缺的是某个已确立实体从未被确定过的属性 → 进入 COLLAPSE
      └─ 信息不足，但只是因为对象/实体本身未接地 → 边界响应，不进入 COLLAPSE（现有 grounding gate 已挡住多数这类情况）
  → COLLAPSE（仅在上面触发时进入）
      Continuity Resolver 提出最小补全命题
        → 陪审团（3 名同源判官，先跑起来）+ 书记员（多数通过 / 编造单票否决 / 含糊算不放行）校验
        → 放行：新命题以 status=active、height=当前 Height 写入真相文档库，回到 ADJUDICATE 用新命题重新裁决
        → 不放行：边界响应，不虚构结果
  → COMMIT     裁决结果本身也作为一条或多条 source=attempt-outcome 的命题写入（一次真实发生的失败也创建 Height，与只读失败/绑定失败区分，沿用 world-constitution.md 现有规则）
  → NARRATE    世界反馈者角色，把这次 COMMIT 的结果 + 相关命题，投影成玩家收到的原始感官文本
```

**GROUND 阶段不变。** 这不是本次重设计的对象——它已经在正确履职(挡住无中生有的实体),两轮真人测试暴露的问题从来不是"编造进来了",是"合法意图被表达空间卡死了"。混淆这两件事、把 GROUND 也推倒重来,是不必要的范围扩张。

## 4. NARRATE 阶段需要的一个具体修补

`world-feedback-narration-spike` 发现的材质词泄漏,不是"再小心点"能解决的模糊问题,是一个具体的、可以直接改 prompt 应对的漏洞:世界反馈者会把自己在描述里用的比喻("像金属"）当成后续轮次可以直接使用的确定事实,即使这个词从未被玩家 alias、且相关感官通道(嗅觉)明确关闭、永远无法真正确认材质。

**建议修补**:在 `世界反馈者手册.md` 第五章(词)的判定流程(5.3)里,明确一条现在没写清楚的规则——**alias 的主体只能是玩家,反馈者自己在描述里使用的比喻/近似说法,不能在后续轮次里被自己当成已确认的类别/材质词继续使用**;如果反馈者需要在多轮里保持对某个未定性质的一致描述,应该继续用同一个比喻或质地描述(比如反复说"反光方式像金属那种"),而不是滑向直接断言("金属表面")。这条修补本身也应该拿真实调用重新测一次,不能只改完 prompt 就当作已解决。

## 5. 明确未覆盖、不是本文档要解决的问题

沿用 `architecture-redesign-plan-v0.1.md` 第 9 节的非目标,这次重申仍然有效:不追求连续物理仿真、不追求 LLM 自由生成世界规律、不追求一次性生成完整远方世界、不追求首版解决 NPC 社会和多主体并发这种复杂问题。四轮实验也完全没有触碰这几块,不能假装它们已经被间接验证。

## 6. 下一步

不建议继续做更多孤立的 prompt 实验——已经验证到能收益递减的程度。建议:

1. **最小编码集成切片**:把第 2 节这条主链真的接成能跑一轮完整交互的代码(哪怕是脱离正式 runtime 的独立脚本),验证这几块接在一起会不会冒出孤立测试测不出来的新问题。这是当前最高优先级,因为集成风险和单点风险是两类不同的风险,后者已经充分验证。
2. **RAG 召回率验证**:需要真接入 Cloudflare AI Search,在有规模的语料上测,不是靠改 prompt 能回答的问题——如果第 1 步的集成切片证明这条主链值得往下投入,这一步就变成必须做的事,不能无限期押后。
3. 材质词泄漏的 prompt 修补,连带重测。
4. 陪审团分歧信号假设:换更有价值判断色彩、而不是纯数值边界的案例重测,或者引入真正差异化的判官,才有可能把这件事说清楚。
