# 愿景、目标与 Demo 方向审查

日期：2026-08-27
状态：accepted correction
范围：研究材料、四份核心设计文档、实施计划与当前 CLI Demo

## 1. 结论

项目愿景没有偏：目标仍是让玩家通过自然语言进入一个持续、自洽、不围绕玩家意愿改写的外部现实。Canon、Commit、Replay、主体认识隔离、World Time 与 LLM 无提交权等可信内核方向继续成立。

偏差发生在开放行动的运行时落地：实现把“模型不能直接决定现实”收紧成“只有确定性代码预先登记的具体动作才能发生”，又把三个安全性纵向案例、CLI 连续输入和脚本化长会话误判为“可供人连续试玩的 Demo”。当前产物应重新定性为**可信运行时纵向切片**，不是已经满足产品目标的文字 VR Demo。

这既包含阶段缺口，也包含方向错误：

- 主动观察、环境投影、具身入口和足够场景事实尚未实现，属于阶段未到位；
- 用具体动词闭合注册表承担开放行动、禁止模型提出任何局部效果候选，属于交互与裁决架构偏差；
- 用安全性和重放门禁替代开放体验门禁，属于计划和验收偏差。

## 2. 证据链

### 2.1 原始愿景与实验

人工实验中的 `Attempt` 是开放接口。主体可以观察、移动、触摸、搜索、组合身体动作并使用环境；行动可以因腿麻、遮挡、距离、阻力或对象反应而失败，但不是因为反馈者没有登记对应中文动词。

实验材料反复显示：

- 世界反馈者代表实然，不能为了玩家意图改写现实；
- Attempt 的拒绝应来自世界，而不是任意裁量；
- 身体是玩家访问世界的接口；
- 观察先提供事实，意义和推断随后形成；
- 世界中必须存在不等待玩家的过程。

因此“开放”与“可信”是并列要求，不能用其中一项替代另一项。

### 2.2 核心目标已经写明但未进入门禁

`demo-goals.md` 已要求自由 Attempt、观察当前空间、自然语言方法表达，并把“每个新动词都必须修改内核硬编码”列为失败条件。但自动门禁主要检查错误提交、泄漏、重放、Height 与 Collapse，没有衡量合理开放行动的落地能力。

### 2.3 协议内部存在结构性冲突

`runtime-protocol.md` 将 `operation` 规定为闭合注册表条目，并要求确定性 Adjudicator 唯一构造 Candidate Delta；同时禁止模型提出 RealityDelta 或世界值。在没有通用物理模拟器的前提下，这只能支持程序员事先写过的动作，无法兑现开放 Attempt。

可信边界应限制模型的权力，而不是删除其参与开放语义裁决的能力。模型可以提出受来源约束的局部效果候选；确定性系统仍负责实体绑定、可见范围、事实读取、能力和关系不变量、Collapse 权限、候选验证以及唯一 Commit。

### 2.4 当前实现证明了偏差

当前 compiler 只把含“开/推门”的目标编译为 `open`，另有独立 `wait`；RuntimeSession 只分发这两个 operation。Query 又特判为读取门的开合状态。Genesis 没有足够的空间内容、视觉关系、光照和主体感官事实，Experience 主要由动作结果附带生成。

因此“看看四周”返回 `TARGET_UNGROUNDED` 不是偶发模型错误，而是当前架构没有把主体周围的感知范围当作合法观察目标。

## 3. 保留项

以下实现与规范继续保留：

- 玩家输入只产生非权威意图和候选；
- 玩家夹带的结果或隐藏事实不能进入 Canon；
- LLM 永远没有 Commit 权；
- 所有世界变化经过统一 Validation 与 Commit；
- Finalized 历史只追加、可重放；
- Canonical Reality 与 Experience/Epistemic Ledger 分离；
- Observation 必须有合法来源；
- World Height 与 World Time 分离；
- Process 可以独立于玩家推进；
- 模型故障和不支持边界不会伪装成世界事实。

## 4. 必须纠正的设计

### 4.1 感知成为一级世界接口

- 会话进入或恢复时可以投递当前位置的初始环境观察；
- “看看四周”“听听外面”“感觉身体”不要求绑定一个具体物体；
- 感知 scope 由主体位置、姿态、感官、注意、光线、遮挡和空间关系计算；
- “门现在开着吗”这类读取已有认识的 Query，与转头、搜索、仔细检查等 Perception Attempt 分离；
- Observation 可以不改变 Canon，但耗时或改变姿态/注意的观察可以创建世界事件。

### 4.2 从具体动词 handler 转为可组合世界原语

闭合的应是可信效果类型和世界不变量，而不是玩家能说的中文动词。首版评估以下通用原语：

- perceive；
- move / orient；
- contact / apply-force；
- hold / release / place；
- change-relation（开合、包含、支撑、遮挡、连接）；
- communicate；
- wait。

自然语言动作可以组合为多个原语。对象通过 affordance、材料、状态和关系约束参与裁决；不为每个表面动词增加专用内核分支。

### 4.3 允许非权威局部效果候选

LLM 可以在获得最小相关世界切片后提出 `ActionProposal`，包括：

- 原文目标和方法；
- 相关实体 mention 与候选绑定需求；
- 使用的身体部位、工具或接触关系；
- 所需前置条件；
- 候选局部效果和耗时；
- 无法判断的依赖。

候选效果只能使用获准 effect schema 和当前可引用实体。模型不能创建 Canonical ID、不能把玩家断言当证据、不能读取未授权 Canon、不能自行 Collapse、不能 Commit。Validator 可以接受、缩减或拒绝候选，但不得为迎合玩家补写效果。

### 4.4 明确“有限世界内的开放行动”

首版不承诺任意宇宙和完整物理模拟。开放性定义为：在当前已建模因果范围内，玩家可以自由表达并组合合理行动；系统优先尝试落到通用原语和对象能力，而不是匹配命令句式。确实超出世界 schema、因果范围或验证能力时，诚实返回产品边界。

## 5. 计划纠正

1. 将已完成 Phase 0–7 重新定性为可信内核与交互壳基线；不回滚其成果。
2. 在新增更多场景对象前，完成感知场、开放行动 IR 和候选效果验证 spike。
3. 建立最小但足够稠密的房间：位置、边界、光照、遮挡、可见对象、可达关系、主体姿态和感官。
4. 实现初始观察、环顾、定向观察和身体感知。
5. 用通用原语实现一组组合行动，不为测试句逐句增加 handler。
6. 从 `fc1.txt`、`fc2.txt` 和手册抽取开发时不逐句编码的盲测语料。
7. 通过自由会话门禁后，再加入容器、纸条、NPC/动物和 Web UI。

## 6. 新的 Demo 判定

只有同时满足以下条件，才可以再次称为“可试玩文字 VR Demo”：

- 玩家进入后能获得合法的环境第一屏；
- 无目标环境观察和针对对象的观察都能成立；
- 常见合理动作的多种自然表达不依赖固定命令模板；
- 至少一组未逐句预编程的组合行动能够产生世界内成功、部分成功或物理失败；
- 世界边界与产品能力边界被明确区分；
- 开放行动不破坏既有 Canon、认识、重放和安全不变量；
- 真实自由会话中系统不是主要以 `TARGET_UNGROUNDED` 或 `CAPABILITY_UNSUPPORTED` 回应。

在这些条件满足前，CLI 应称为开发者纵向切片 Demo。
